# Fast orthogonal Smith formulas

Version 0.8 exposes the closed type B and D multiplicity formulas as
`orthogonal_smith()`. It computes exact integers with truncated Gaussian
polynomials, without building a Weyl group, Schubert matrix, or Smith basis.
The mathematical inputs are the internally audited, unpublished
[type B proof](TYPE_B_GENERAL_SMITH.md) and
[type D proof](TYPE_D_EVEN_GLUING_THEOREM.md).
The [proof-status guide](PROOF_STATUS.md) records their scope and sources.

## One-degree API

```python
from sage_borel import orthogonal_smith

result = orthogonal_smith("D", n=4, k=2, degree=4)
assert result.multiplicities == {1: 1, 2: 2}
assert result.rank == 3
assert result.cohomological_degree == 8
assert result.saturation_exponent == 2  # index = 2^2
assert result.saturation_index() == 4
assert result.smith_factors() == (1, 2, 2)
assert result.unit_gluing_dimension == 1
assert not result.is_saturated
```

The signature is

```text
orthogonal_smith(family, n, k, degree, *,
                 sector="full", normalization="normalized")
```

Parameters follow the Kumar papers and `classical_borel`:

| Argument | Meaning |
| --- | --- |
| `family` | `"B"` or `"D"` (case insensitive) |
| `n, k` in B | `OG(n-k, 2*n+1)`, with `n >= 2` and `1 <= k < n` |
| `n, k` in D | `OG(n-k, 2*n)`, with `n >= 4` and `2 <= k < n` |
| `degree=d` | Polynomial degree; the target is cohomological degree `2*d` |
| `sector` | `"full"`, `"square"`, or D-only `"euler"` |
| `normalization` | `"normalized"` or the explicitly scaled `"character"` form |

The normalized source is generated by
`q_i=e_i(x_(n-k+1)^2,...,x_n^2)`. In D it also contains
`p=x_(n-k+1)*...*x_n`, with `p^2=q_k`. These correspond to the
papers' `e_i` and `bar h_{1,k}`. The square sector is `ZZ[q_1,...,q_k]`;
the Euler sector is the **module** `p*ZZ[q_1,...,q_k]`, not the algebra
generated by `p` alone.

```python
square = orthogonal_smith("D", 4, 2, 4, sector="square")
euler = orthogonal_smith("D", 4, 2, 4, sector="euler")
assert square.smith_factors() == (1, 2)
assert euler.smith_factors() == (1,)

# Combining sectors has an integral correction: (1,1) becomes (1,2).
assert orthogonal_smith("D", 4, 2, 4).smith_factors() == (1, 2, 2)
character = orthogonal_smith("D", 4, 2, 4, normalization="character")
assert character.smith_factors() == (16, 32, 32)
```

The character option uses `4^i*q_i` and, in D, `2^k*p`.
It multiplies each degree-`d` factor by `2^d`, including in the Euler
sector. It does not select a Spin lattice or an arbitrary representation.

## Compressed results

`OrthogonalSmithSummary` is immutable. Its fields and accessors are:

| Accessor | Result |
| --- | --- |
| `family, n, k, degree, sector, normalization` | The specified problem |
| `cohomological_degree` | `2*degree` |
| `exponent_multiplicities` | Tuple of `(e, count)` for factors `2^e`; zero counts omitted |
| `multiplicities` | Fresh dictionary `{factor: count}`, including units |
| `rank` | Number of nonzero Smith factors |
| `saturation_exponent` | Exact `E` such that the saturation index is `2^E` |
| `is_saturated` | Whether `E=0` |
| `unit_gluing_dimension` | Normalized unit gluing in full D; zero for B and sector-only reports |
| `smith_factors(max_rank=100000)` | Expanded sorted tuple, with an explicit allocation limit |
| `saturation_index(max_bits=1000000)` | Integer `2^E`, with an explicit bit-length limit |
| `as_dict()` | JSON-safe compressed metadata, without expanding factors or the index |

An image of rank zero has an empty factor list, index one, and is saturated.
Units count toward rank even though they contribute no torsion.
`unit_gluing_dimension` describes the normalized geometry and is unchanged
by the character scaling; it does not count unit factors of that scaled form.
Nonintegral numeric arguments, booleans, negative degrees, and unsupported
families or ranges are rejected rather than silently coerced.

```python
import json

large = orthogonal_smith("D", n=200, k=80, degree=1000)
assert large.rank > 100000
assert large.saturation_exponent > 1000000
json.dumps(large.as_dict())  # remains compressed

try:
    large.smith_factors()
except ValueError:
    pass  # use multiplicities; expansion exceeds the default limit
else:
    raise AssertionError("large factor list was expanded")
```

Unlike `IntegralDegreeAnalysis`, the summary has no coefficient matrix,
Schubert labels, ambient dimension, membership test, or preimage. Its factors
classify an abstract lattice inclusion up to integral basis changes; they do
not locate the Smith directions inside the original Schubert basis.
Use [A.integral_degree(d)](INTEGRAL_IMAGES.md) when those directions matter.
This method is not automatically substituted for arbitrary `GeneratorAlgebra`
inputs: changing, adding, or scaling generators can change the integer image.

## Mathematics and algorithm

Let `L_d` be the selected image in `H^(2d)(X;ZZ)` and set
`S_d=(L_d tensor QQ) intersect H^(2d)(X;ZZ)`. If `m_e` is the returned
multiplicity of `2^e`, then

\[
S_d/L_d\cong\bigoplus_{e\ge1}(\mathbb Z/2^e\mathbb Z)^{m_e},
\qquad [S_d:L_d]=2^{\sum_e e m_e}.
\]

This index is in the selected rational image's saturation. It is not
necessarily an index in all cohomology, and the quotient is not torsion in
the integral cohomology of the flag variety itself.

For B put `ell=min(k,n-k)`, `r=floor(n/2)`, `c=ceil(n/2)`.
In degree `d=2m`, the multiplicity of `2^e` is the coefficient of `q^m` in

\[
q^{ec}{r\brack e}_q
\sum_{j=0}^{\lfloor(\ell-e)/2\rfloor}
q^{j(c-\ell+j)}{r-e\brack j}_q
{c-e-j\brack \ell-e-2j}_q.
\]

Here the Gaussian polynomial `[v choose u]_q` counts partitions in an
`u` by `v-u` rectangle. B has zero image in odd polynomial degrees.
The function evaluates only the coefficient required for the chosen degree.
It uses the Gaussian product formula, truncates power series, and reflects
coefficients across the middle of a palindromic Gaussian product when useful.
Caches are local to each call. It never enumerates rectangle partitions.

For D the square contribution is the B result at `(n,k,d)` and the Euler
contribution is the B result at `(n-1,k,d-k)`. The point boundary `(k,k)`
contributes one unit at degree zero. For `k=2h`, set

\[
I_{n,2h}(q)=q^{h(\lfloor(n-2h)/2\rfloor+1)}
{h+\lceil(n-2h)/2\rceil-1\brack h}_q.
\]

Its coefficient at `q^(d/2)` is the unit gluing dimension; it is zero
for odd `d` or odd `k`. Subtract this count from exponent zero and add
it to exponent one. The general D proof justifies that there is no
further gluing correction. Negative predicted counts raise an error.

## Verification and performance

[Tests](tests/test_orthogonal.py) compare the Gaussian implementation with
the distinct beta-number partition rule in every degree of 36 rectangles,
174 recorded B Smith lists, 414 recorded D sector/full lists, and fresh BGG
integer matrices, including scaled generators. Input boundaries, odd tails,
the one-head Euler boundary, and output limits are covered separately.
These checks validate the implementation; the arbitrary-rank proof remains
in the linked research notes.

The [benchmark](benchmarks/orthogonal.py) records exact compressed outputs,
timings, and source hashes in [its report](benchmarks/orthogonal-results.json).
It includes rank-nine, rank-40, and rank-200 examples. Timings describe the
recorded machine and degree, not a bound on all parameter sizes.

Run from `borel/` inside Sage:

```sh
PYTHONPATH=src sage -python -m unittest tests.test_orthogonal -v
PYTHONPATH=src sage -python examples/orthogonal_smith.py
PYTHONPATH=src sage -python benchmarks/orthogonal.py
```
